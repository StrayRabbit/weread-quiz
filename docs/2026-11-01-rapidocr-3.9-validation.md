# RapidOCR 3.9.0 升级验证

## 变更范围

- `rapidocr-onnxruntime 1.4.4` → `rapidocr==3.9.0`；显式声明 `onnxruntime>=1.17`，本机仍使用 1.31.0。
- 使用 3.9.0 包内默认 PP-OCRv6 Small 检测与识别模型；实际初始化确认模型文件已随包存在，无需另行下载模型。
- OCR 内核把新版 `RapidOCROutput.boxes/txts/scores` 转为既有 `(box, text, confidence)` 行；保留空结果和异常时返回 None 的行为。
- PK 读取器使用父类预热，题号读取器同步使用新版输出；所有推理仍传 `use_cls=False`。
- 未修改门控阈值、几何、模型请求、超时预算、点击策略或用户已有的 `pk.py` 修改。未启动真实答题、未调用远端模型。

## 测试

- 升级前：`uv run --no-sync python -m pytest -q`，20 passed。
- 新兼容测试先在旧实现下运行：7 failed、4 passed；失败覆盖新版输出、PK/daily 初始化和题号读取路径。
- 迁移后：31 passed，包含 11 项新增测试。
- `python -m compileall -q src/weread_quiz` 通过。
- `uv pip check` 通过。首次同步发现原环境 pywin32 312 缺失 RECORD，重装原版本后已恢复完整性；不为此新增项目依赖。

## 结果边界

门控通过只代表结构与置信度达标，不等于逐字准确率 100%。例如新版仍保留个别题干漏字或空格/标点差异；新旧速度为单轮观测，不是多轮统计基准。升级能减少这组样本的 OCR 回退，但不能直接解决远端 HTTP ReadTimeout。
