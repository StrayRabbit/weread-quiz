# 设计说明

本文记录 weread-quiz 的内部设计与关键取舍，**为什么这么写**。面向维护者，不是使用手册；
使用请看 [README](../README.md)。

## 工作原理

```
微信窗口 (window/finder.py)
   ↓ 整窗截图
capture.py (mss 抓屏)  ──→  RunRecorder 落盘 data/runs/<子命令>/<时间戳>/
   ↓
advance.py     自动推进到答题页（只在正式模式）
               按 route.py 的白名单精确匹配文字 → 点击前复核 → 点击
   ↓
pk_hybrid.py / daily_hybrid.py   混合读取器
               本地 RapidOCR 读题 + 置信度门控；门控不通过回退图片路径
   ↓
blank.py      填空题的横线是画出来的，OCR 读不到
               按像素找出横线 → 题干补成「____」（见下方设计要点）
   ↓
vision.py      视觉模型一次调用同时完成「识别题目」+「判答案」
               容错：剥离 <think> 块 / 修补未转义引号 / 裸序号兜底
   ↓
buttons.py     按青色边框几何检测定位选项按钮（不用模型给的坐标）
daily_buttons.py  每日一答的深蓝灰填充按钮，几何参数不同
   ↓
screen.py / daily_screen.py   题干区二值化帧差 → 判定换题、等题面稳定
   ↓
click.py       图像坐标 + region 原点 → 物理像素 → pyautogui 点击
```

## 设计要点

每一条都是踩过坑之后才定下来的，写在这里是为了让后来的人不用再踩一遍。

**读题：本地 OCR 优先，模型只判下标。**
RapidOCR 在同一批截图上选项命中 5/6，比整图问模型快一大截，输入 token 从
790 降到 231。但 OCR 会**自信地认错字**，所以加了置信度门控：选项数须等于
按钮数、最低置信度须达阈值，任一不满足就回退整图问模型。阈值靠 `run.log`
里每题记录的置信度校准。

**阈值怎么调。**
`OCR_MIN_CONFIDENCE` 默认 0.7。每局结束终端会打一行
`OCR 快路径：命中 9/10，回退图片 1 次（原因：本地 OCR 置信度不足）`——
「原因」就是本局回退的分类统计，完整读数（每个选项的置信度）在 `run.log`
的「图片路径 回退原因」行里。2026-11-02 实测被拒的是 `0.68`、`0.66` 这种
**擦着阈值**的值（一局 10 题回退 0~1 次），说明 0.7 定得不算离谱；只有当
回退集中在 0.60 上下时才值得往下调。**别降太多**：PK 的选项常常是单字
（`['擐','乘','啤']`），认错一个字就是整题答错，阈值宁高勿低。

**填空横线要靠像素补，题干要按画面顺序拼。**
填空题的横线是**画出来的图形**，OCR 读不到 —— 本地读数会变成没有空位的
「女红男」，模型只能靠猜这里本来有个空。`blank.py` 用像素把横线找出来，
在题干里补成「____」。横线不能靠长度认：「一」「二」「三」的横笔跟填空线
差不多长，靠的是「附近没有文字框压着」+「上下没有别的笔画」两条判据。
另外本地 OCR 原先把同一行的文字**按文字排序**拼（不是按横向位置），
「黑云翻墨未遮山，__跳珠乱入船。」会拼成「跳珠乱入黑云翻墨未遮山船。」——
词序反了，模型直接答不出下标。现在一律按画面阅读顺序拼。

**界面类型判据只能是题号行。**
「第 N 题·共 M 题」只有答题页有，匹配页和结算页都没有。这条判据零网络开销、
不依赖模型，且比模板匹配更抗改版（改版不会去掉题号行）。
**关键在于它必须与「读数能不能答」（选项数 / 置信度）分开判。** 绑在一起的
代价是：一帧读数不合格 → 整份读数被丢掉 → 连「这是不是答题页」的结论也
一起丢了 → 程序只能继续等，而每一帧都是同样的失败，**永远等不到**。
分开之后：题号行读到就确认界面类型（读数不合格也照样确认），但那份残缺读数
只用来证明界面，不用来答题。

**题号行有两种写法，都要认。**
daily 卡片在最后一题把「第 N 题·共 M 题」换成「最后一题」。只认带数字的那种，
最后一题就没有题号证据 —— 门控判否、被迫回退图片路径，题干里还会混进
「最后一题」三个字（2026-11-02 实测：那题选项读得又准又全，置信度 0.99，
却因为这一行被判否）。「最后一题」算题号证据，但**编号读不出就是 None，
绝不猜**。

**按钮位置不用模型给。**
实测模型返回的按钮 y 坐标偏差可达几十像素，而按钮本身只有 43 像素高，点下去
必然落空。改用**几何检测**：PK 认青色边框，daily 认深蓝灰填充。边框是几何
形状，不受选项文字长度影响。

**自动推进用文字定位，不用几何按钮检测。**
匹配页的「自动匹配」和答题页的选项按钮都是青色边框、几何几乎一样；daily
入口页的卡片还会跨过 daily 的按钮下边界。**文字是语义判据**：改版不会把
「自动匹配」改成别的词。匹配必须**精确相等**，不能用子串包含 —— daily 入口
页上有一行「瓜分一百万书币体验卡」的副标题，子串匹配会误命中一个根本不存在的
按钮。

**白名单按路线分开。**
daily 活动页上并排两张卡片，两个白名单都列上它们的话，程序会点上面那张，
「瓜分书币」路线静默地跑成「瓜分天数」路线，日志里看不出任何异常。分开后
两边互斥，串台不可能发生。

**点击前要复核。**
OCR 有几百毫秒的固定开销，期间界面可能已经变了。复核重抓一张图，确认目标
文字**仍以精确相等的形式存在**且位置偏差 ≤ 12 像素。复核失败分两种：目标
**不见了**（界面在跳转）→ 只放弃本轮；目标**跑到了别的位置** → 该目标本轮
作废，不再点它。

**换题判定靠题干帧差，不靠「按钮还在不在」。**
下一题渲染前的那一两秒按钮仍然在，用它判断会把同一题当成新题再点一次。
题干区二值化帧差区分度很高：同一题严格为 0，真换题上千像素。
判定带还要**限定横向区间**（PK 是 x40-390）—— 截图左右边缘可能混进桌面上
另一个窗口的浅色像素，那条浅灰竖线会随桌面重绘抖动，产生超过换题阈值的假
变化。限定后假变化归零，真换题的帧差几乎不受影响（题干正文实测 x=72~350，
渗入区实测 x≤7 与 x≥423，两头都有大余量）。

**「就绪」= 有按钮 + 题干已换 + 不在答后揭示态。**
三条缺一不可：按钮在渐显动画里**最先**画完、题干最后画完，只看「有没有按钮」
会拿到一张「按钮已回、题干还是上一题」的半成品帧；而答对后界面会**先停一阵
才推进** —— 正确选项整条染成青绿色、比分更新，但题干和题号纹丝不动，
**「题干没变」不等于「没渲染完」**。揭示态一旦漏判，等待循环第一轮就会把
揭示帧当成「下一题」返回，白白吃掉一整轮。

**DPI 必须最先初始化；窗口要按标题挑，不要按面积。**
mss 抓屏返回物理像素、pyautogui 点击用逻辑像素，系统缩放非 100% 时两者不
一致，所有点击都必须走 `dpi.py` 换算。另外微信客户端主窗口（标题「微信」）
比小程序窗口（标题「微信读书」）**面积更大**，只按面积挑会选中主客户端 ——
抓错窗口整局作废。所以 `finder.pick_largest_wechat` 优先精确标题「微信读书」，
找不到才退回按面积取最大的。多显示器时 `pyautogui` 的点击坐标按主屏尺寸
归一化，跨屏点击实测可用。

**HTTP 客户端共享 SSL context，并在开局前预热。**
`httpx.Client()` 光构造就要上千毫秒 —— httpx 会建 3 个 transport，每个都
重新把 CA 证书包读进内存。传一个**进程内共享**的 SSL context 进去，构造降到
几十毫秒；客户端又是惰性创建的，所以开局前先 `warmup_client()`，把这段开销
挪到「还没开始答题」的时候。注意这是**本地**开销，与模型无关：模型端没有
「第一次特别慢」这回事，快慢全看服务端排队与思考量。

**同一条带不该 OCR 两遍。**
等待阶段读题号行用的带和答题阶段读题号用的是同一条，被 OCR 了两遍。现在
等待阶段把读到的**原文**带出来直接解析复用，省掉一次几百毫秒的 OCR，结果
完全一致。

**本地判否和模型失败必须分开。**
这是两种**处置正好相反**的失败：

| 失败点 | 含义 | 正确处置 |
|---|---|---|
| 本地门控判否 | 这一帧本地就读不出（**一次网络都没发**） | 再等一帧，不阻塞 |
| 模型侧失败 | 请求**已经发出**但没取到答案（超时/网络） | 已经花掉时间，不能再来一次 |

原先用一个异常类型同时表示这两件事，日志会把**模型侧超时**写成「本地 OCR
未读出，继续等」—— 程序以为只要再等一帧就好，实际每一轮都要再发一次最长
阻塞的请求，两次就能吃掉整道题。现在分成 `OcrRejected`（判据结论）和
`AnswerUnavailable`（调用失败）两个类型。

**失败要有上限，也要能恢复。**
文本路径连续失败 3 次就进入纯像素轮询，冷却 30 轮后允许再试一次：无限重试
会吃掉整道题也烧 token，而**永久禁用**更糟 —— 服务端早就恢复了也没人再试。
冷却期里图片路径也跳过：换一条路并不能躲开「服务端在慢」这件事。

**文本路径单次限时，剩下预算留给图片路径。**
单题预算只有 10.5 秒（倒计时 12 秒减去点击预留）。文本路径如果按整个剩余
预算来等，一次慢请求（实测有过 10 秒没回的）就把预算吃光 —— 超时后只能
蒙答，而二选一蒙对也只有一半机会。所以文本路径单次最多 5 秒；超时后**不再
重试文本路径**，而是直接走图片路径（模型读整张图，实测 1.5~3 秒）。
剩下的预算不够跑图片路径（< 3.5 秒）时才放弃蒙答。

旧的判据是「文本路径超过 3.2 秒就不再级联图片路径」—— 那等于假定图片路径
也要 11 秒；实际上图片路径拿的是**剩余预算**（通常还有 5~9 秒），够跑。

**超龄时蒙一个，而不是丢弃。**
PK 里超时的惩罚与答错相同（该题不得分），所以点第一个有 25~33% 机会，
什么都不点是 0%。蒙答会**现抓一张新图**再定位按钮 —— 超时意味着已过去十几秒，
屏幕内容可能早换了题，用旧坐标点会点到别的题上。`GUESS_ON_FAILURE=0` 可关闭。
OCR 快路径不受图龄闸门约束（图只在本地用一次），图片路径仍受约束。

**答后反馈要赶在渐隐之前取帧。**
答对/答错的颜色只亮很短一瞬，末题之后直接进结算页。取色同时看绝对颜色和
相对点击前的色相位移，颜色渐显到一半、或整页渐隐压暗时都判得准；整页渐隐
只会得到「未确认」，不会被当成答错。

**留证一题一张。**
每题只存一张 `q{NN}_before`（模型输入的原图，跳过的题也留 —— 它恰恰是最需要
证据的一题），加上异常时的 `transition_unknown` 和停止时的 `stop_status`。
等待期不再每 4 帧定期落盘：那批相邻帧之间只差一个倒计时数字，对排错的边际
价值很低，却让「哪张是哪题」要看编号才数得出来。

**终态只认明确文字，不从星级推测。**
结算页判读只认明确的胜负文字。未知页面超时只报告「流程中断（已点击 N 题）：
原因」，不猜答错或今日机会已用完。

**启动器的中文显示。**
`.bat` 文件本身是**纯 ASCII** 的，中文提示全部由 Python 输出。原因是
cmd.exe 读 `.bat` 时按**系统 ANSI 代码页**（本机 GBK）解码：UTF-8 编码的
bat 会被按 GBK 解码，多字节序列错位后某一行被从**中间切开**，cmd 把前半截
当命令执行：

    '锟藉埌灞忓箷宸︿笂瑙掋' is not recognized as an internal or external command

（那串乱码解码回来正是早期 banner 文案「想中止：把鼠标猛地推到屏幕左上角。」
的后半段。）
`chcp 65001` 只会更糟 —— cmd 改代码页后用**新**代码页的字节偏移重新定位
文件，切得更歪。

所以启动器里是：纯 ASCII 的 bat + `chcp 65001` + `PYTHONIOENCODING=utf-8`，
中文由 `weread_quiz/__main__.py` 根据 `WEREQ_BANNER` 环境变量打印。
批处理文件还必须是 **CRLF 行尾**（LF 会让整行被当成一条命令）—— 仓库根目录的
`.gitattributes` 已经把这条规则固定住（`*.bat text eol=crlf`），clone 之后不用
再操心。启动器本身由 `tools/write_launchers.py` 生成，**改启动器时改生成器**，
不要手改 `.bat`。

**紧急中止用 Esc，角落 failsafe 留着兜底。**
中止方式从「把鼠标猛地推到屏幕左上角」改成「按 Esc」—— 后者好懂得多，
而且程序正在控制鼠标，让用户去够左上角本身就是个坑。实现是 `abort.py`：
后台线程装**低级键盘钩子**（`WH_KEYBOARD_LL`），回调里认 Esc 的按下沿。

两个实现上的坑：

- **不能用 `RegisterHotKey`。** 它是系统级热键，Esc 会被**吃掉** —— 微信自己
  就收不到这个 Esc 了，而 Esc 恰恰是用户想关掉弹窗时按的键。低级钩子只是
  旁听，不抢键。
- **不能用 `GetAsyncKeyState`。** 它反映的是**调用线程处理过的键盘消息**；
  监听线程没有键盘消息可处理，读到的一直是初始状态。实测合成按键完全检测
  不到。低级钩子则由系统把消息投到安装线程，消息循环里必然收到。

中止点放在**每次点击之前**（`click_box`）和各轮询循环开头：模型请求期间按 Esc
不会立刻打断那次请求（httpx 没法中断），但请求一返回就不会再点下去。
角落 failsafe 保留 —— 钩子装不上时（安全软件拦、环境不允许）它还在，是唯一
的兜底。代价是程序自己在动鼠标，误触左上角会误中止（旧行为，没变）。

## 每日一答链路

Daily 与 PK 使用相同的阶段划分，但保留独立的按钮几何、OCR 阈值和终态规则。
`recognition.py` 集中两者共用的本地补读、判否证据保留、完整选项文本求答和单次图片级联；
`pk_hybrid.py` / `daily_hybrid.py` 保留各自的预算策略、模型输入、题号缓存和统计日志。
不把 PK 倒计时 / 加时规则与每日一答固定预算 / 答错终止规则混在一起：

1. **首题本地确认**：先检查题干渲染、揭示态及连续两帧的题干、按钮布局和选项文字稳定，再用本地 OCR 的题号证据确认页面。选项不全不影响界面确认，但不会把残缺选项发给文本模型。
2. **复用预读**：通过门控的读数交给当前题处理，最多一次文本求答案（上限 5 秒，受剩余预算约束），不重复 OCR。判否则直接走裁图图片路径。
3. **统一预算**：单题识别默认共用 9 秒绝对预算，切换路径不续期；文本请求上限 5 秒，并尽量给图片路径保留 3.5 秒。本地预读沿用独立短请求规则，图片结果另受 8 秒图龄保护。
4. **安全点击**：所有答案（包括失败后的蒙答）都先重抓并确认同题，再用新图定位。采集时刻未知、图片过期或页面变化时跳过；Esc 中止向外传播。`--dry-run` 不点击、不计入实际作答数。
5. **独立终态确认**：保留 19 秒换题总预算、连续两帧就绪和严格终态文字确认。无按钮不代表答错；不明确时报告中断，不使用任何复活道具。

本地 OCR 不可用时直接走图片路径。只有像素判据已确认画面像答题页、但 OCR
持续无法读到题号时，首题等待才允许一次限时图片兜底，不循环请求模型。
每题用量归属于该题，等待阶段的抓屏、OCR、请求和轮询耗时写入 `run.log`。

**模型失败排查**：请求超时直接使用剩余预算，不再固定扣除 1.2 秒；客户端构建
由开局预热承担，不能把它误当成每次 HTTP 读超时的额外耗时。仍保留请求后的
绝对 deadline 检查，超期答案不能用于点击。图片返回格式无效时会记录受控的
`parse_reason`（如 `missing_json`、`invalid_json`、`empty_stem`、`empty_options`），
以及整个读题的 `elapsed_ms` 和剩余 `remaining_ms`，不记录回复原文。合法 JSON
中题干为空也会被拒绝。daily 的每题日志会显式标注 `蒙答`、按钮序号和原因。

图片回退需要模型端点确实支持图像输入；不能只因为文本请求可用就认定识图
可用。更换型号后应在实际文本、图片预算内验证（见上方关键常量），而不是通过放宽解析
或延长到超出题窗的时间来掩盖失败。

## 模型选型

默认 `MiniMax-M3.1-Flash`。同一批真实 PK 截图上与旧配置 `MiniMax-M3` 的对照：

| 指标 | MiniMax-M3 | MiniMax-M3.1-Flash |
|------|-------------|--------------------|
| 视觉路径中位延迟 | 5.50s | **4.17s** |
| 视觉路径 p90 / max | 8.33s / 14.16s | **5.54s / 6.63s** |
| 超 8 秒超龄闸门（→ 蒙答） | 2/12 | **0/12** |
| 「114是什么号码」单题稳定性 | 5/8 | **8/8** |
| 界面分类（匹配页/结算页/答题页） | 6/6 | 6/6 |

两处改动带来的实际收益：**max 从 14.16s 降到 6.63s**，直接消除了「模型慢到
撞上 8 秒超龄闸门 → 蒙答」这条路径；「114是什么号码」原本单题就有 3/8 的
概率答错，换成新模型后 8/8 稳定。

**换供应商时注意 `MODEL_THINKING=0` 的行为差异**：`thinking={"type":"disabled"}`
是 MiniMax 的**私有扩展**，只有 MiniMax 端点会发这个字段（判据见
`vision._is_minimax_endpoint`，同时看端点 URL 和模型名，以覆盖本地代理转发）。
别的供应商不认它 —— 宽松的忽略，严格的直接 400。

`MODEL_THINKING=1`（默认）不要关：实测快 312ms/题，但 10 道真实题里 2 道的
答案会变（且变的都是错答案）。见 `tools/bench_thinking_ab.py`。
